# 最终交付入口

本目录用于将当前最终源码、论文和必要证据整理成竞赛提交文件，不是新一轮算法开发。

## 最终提交对象

依据已提供的《全国大学生数学建模竞赛论文格式规范（2026年修订稿）》：

1. `参赛论文.pdf`：独立文件，不压缩，不超过20MB。电子版第一页为摘要，不含承诺书和编号专用页；正文无目录且不超过30页；附录页数不限，包含支撑材料完整文件列表和建模所用完整源码。页边距至少2.5厘米，摘要起连续页码。
2. `支撑材料.zip`：单一ZIP/RAR，不超过20MB，含完整可运行程序、依赖与运行说明、必要自主数据及中间图表、实际测试对应的原始导出日志，以及AI使用详情。不得把整个Git仓库或历史交付包作为支撑材料直接上传。

纸质承诺书和编号专用页单独处理，不加入上述两个电子文件。所有提交文件及元数据均需匿名检查。

## 当前尚未完成的提交条件

当前远端第一二问为既有完整稿，第三四问为独立章节；尚无已核验的四问合并最终论文及完整代码附录。不要把`论文_第一二问.pdf`改名后充当四问最终论文。

本机正式加密日志不在公开仓库中；第三、第四问各三次原始导出日志须按本机记录关联，保留原文件名，不用演练日志代替，不解密或改造加密文件。

已有AI说明含工具型号和人工审核待补字段；最终说明必须据实补全。脚本不会代填人工审核声明、官方案例码或未公开成绩。

## 整理步骤

`prepare_submission.py`执行三个独立步骤：

- `prepare`：只读原仓库，按范围选择源码及依赖、已有结果与图表，建立独立支撑材料工作区，并输出完整附录A、附录B、哈希清单和未完成检查项。此时不生成“可直接提交”的ZIP。
- `archive`：仅把清单中明确的旧压缩包、无运行用途的配置和外部探索资料，先备份到仓库外并核验字节，再移出工作区。不会删除正式日志、模拟器、数学源码或未跟踪文件；不提交、不推送。
- `finalize`：核对完整论文、AI说明、各问三次正式日志映射、支撑文件哈希、文件清单、大小及人工复核状态后，才产生两个提交文件。技术检查不能代替人工核验。

运行例（输出目录必须尚不存在）：

```powershell
python 最终交付/prepare_submission.py prepare --repo . --out "..\CUMCM_提交工作区"
```

补充原始日志、AI PDF和必要外部数据时，通过`--inputs`指定本机JSON，`extra_files`每项填写`source`、支撑包内相对路径`destination`与`description`。新建工作区重新生成附录A和代码附录，不能在清单冻结后偷偷增删文件。

人工确认完整论文和附录后在工作区`提交核验.json`填写论文路径与SHA256、AI文件路径、日志映射和逐项审核结果，再运行：

```powershell
python 最终交付/prepare_submission.py finalize --repo . --out "..\CUMCM_提交工作区"
```

不要把工作区、原始账号配置、审核中间文件或仓库外备份整体上传。程序生成的检查结果中若存在阻塞项，交付状态仍为未完成。

## 清理与匿名边界

缓存、虚拟环境、模拟器安装目录、重复ZIP、旧论文导出、完整聊天记录和本机绝对路径不属于最终提交对象。未采用且未在论文报告的独立实验可移出提交范围；失败实验若用于论文比较，其证据不能删成只剩有利结果。

所提供格式规范的承诺书还明确限制竞赛期间在GitHub等平台浏览、发布或讨论赛题内容。此整理工具不自动推送或公开任何提交材料，不代表已完成竞赛系统提交。
