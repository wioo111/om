## 最终需要上传什么

最终只上传两个电子文件：`参赛论文.pdf`和`支撑材料.zip`，每个不超过20MB。电子论文含摘要、正文和附录，不含承诺书/编号专用页；正文无目录且不超过30页，附录包含完整文件列表和建模所用完整源码。支撑包必须与附录一致并完成匿名检查。

**当前尚不可直接提交。**现有第一二问完整稿和第三四问章节尚未被核验为一份包含完整附录的四问最终PDF；本机正式导出日志、AI工具型号及人工审查说明仍需汇入。缺失项不会由程序猜填，不能将第一二问PDF改名冒充四问成稿。

## 生成交付工作区

在完整本地仓库根目录运行，输出目录必须不存在：

```powershell
python 最终交付/prepare_submission.py prepare --repo . --out "..\CUMCM_提交工作区"
```

输出支撑材料工作区、附录A完整文件表、附录B完整带行号源码、哈希清单及提交核验表。不执行算法，不连接模拟器。动态文件依赖、实际运行与图文一致性仍须人工复核。

将本机正式日志、最终AI说明等通过`--inputs`补入新的工作区并重新生成附录；完成四问论文及逐项复核后，再运行`finalize`。`finalize`未通过时不会生成标为可提交的成品。

GitHub Actions中的`submission-staging-NOT-READY`产物仅是代码和已有资料的组装检查，不能直接作为竞赛支撑包提交。
