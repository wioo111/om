## 使用顺序

1. 在正式测试开始前，可在仓库根目录 PowerShell 运行以下离线检查（不联网，不消耗次数）：

   ```powershell
   .\第三问_一键接入正式.cmd -Check
   .\第四问_一键接入正式.cmd -Check
   ```

   第四问旧版FastP4保留。需要回退时使用 `第四问_一键接入正式.cmd -P4Strategy FastP4`；仅检查旧版使用 `第四问_一键接入正式.cmd -Check -P4Strategy FastP4`。

2. 在模拟器中手动开始对应问题的**正式测试**，等待数据准备和倒计时结束、机器人接口开放。
3. 双击根目录 `第三问_一键接入正式.cmd` 或 `第四问_一键接入正式.cmd`，问题号必须与本局一致。
4. 程序自动进入、串行执行策略并正常退出，窗口显示摘要。完成后在模拟器检查正式日志上传状态并导出支撑材料。

脚本不会启动模拟器或开启、切换、复位测试。HTTP 接口不提供问题号和演练/正式模式验证，因此必须手动选对测试；正式入口也可能连接到已开放的演练，请勿把文件名当作模式检测。正式测试启动即占次数，勿为检查脚本而开启正式测试。

队号沿用本机 `tools/practice.local.json`，也可设置 `JAMMERS_ROBOT_ID`。Python 沿用已有环境，也可通过 `JAMMERS_PYTHON` 指定解释器。正式与演练入口共用进程锁，请勿同时启动。

每次运行保存到本目录 `results/<时间戳>_p<问题号>_<策略>/`，包括 `actions.jsonl`、`console.log`、`result.json`（成功执行后）、`execution.json` 和源码快照。队号脱敏，不读取正式目标位置、目标总数或案例真值。清除数为程序记录，不是官方成绩，也不代表已完成日志上传。

如出现异常或手动关闭程序，不会自动重新进入、退出或重开测试。先查看模拟器中的本局状态，不要直接重复双击。失败详情保存在 `error.txt`；第四问退出码0要求策略正常停止，达到step_limit返回1，不能当成验收通过。程序不能读取正式目标总数，全清仍以模拟器成绩为准，具体查看 `result.json` 的 `stop_reason` 和 `coverage_complete`。

第三问已完成三次正式实机运行，结果见 [第三问正式结果汇总](P3_FORMAL_RESULTS.md) 和 `evidence/p3_formal_summary.json`。第四问本轮168场独立离线对比全清且正常停止，最近两场真实演练分别15/15、16/16；这些是离线及演练证据，不是正式成绩。此次只更新正式入口并离线检查，没有启动正式测试。原始运行目录仅保留本机，GitHub 发布筛选后的汇总，不包含队号、本机绝对路径或加密日志。
